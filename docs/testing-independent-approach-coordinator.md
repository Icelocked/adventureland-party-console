# Independent approach coordinator inventory

Before changing coordinator policy, the user's native Sparkbot situation and repeated recovery attempts showed that one healer-owned route and cohort coverage can stall all actors before their next target. Each updated character must instead route independently toward its own attack radius, check actual native range and sightline, halve the radius and replan when blocked, then resume ordinary combat. The coordinator remains the authority for shared target identity, acknowledged attack permission, pending projectiles and engaged fights.

Risks: beginning attacks from nominations without acknowledgements; clearing a pending/engaged target when the first actor hits while another approaches; reviving one-mover recovery on that hit; bypassing stale/dead/manual/event/loot/realm/instance guards; mixing older clients that cannot own independent routes; and interpreting capability as physical arrival. Retained cases are written before code. All current protocol4 members must advertise independentApproach. Only cohort healer visibility/distance regroup and one-mover control are removed for that mode. All fresh/alive/manual/event/same-place,500ms stability, current selection acknowledgement and attack-evidence ownership remain. Mixed clients retain legacy behavior. A first native hit leaves the capability active and current engaged target retained; each client, not a global phase change, decides when its own route finishes. Actual new attackers still enter existing defense ownership. Native E2E must prove real range/sightline/binary radius routes.

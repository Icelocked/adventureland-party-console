# Terminal settlement and a return-leg peer

## Failure inventory before the reproduction

An existing owned terminal settlement can complete a native-acknowledged final transition without another movement action or a fresh walking lease. A shared returnLeg then publishes leg-arrived and waits for convoy release, instead of sending /convoy-complete. A peer still waits on the post-transition movement barrier. If the settled actor never sends completed:true, its local native completion must not strand the peer forever.

The retained reproduction composes maintained movement service/executor with maintained coordinator movementBarrier and published route ownership. Native leave acknowledgements/positions are declared through the existing isolated native-host fixture boundary. Initial dispatch still requires both actual barrier participants; both native endpoints settle before out-of-band settlement. The test expects the peer to finish with fresh exact actor/runtime/epoch/command/route/revision and native destination records, while no additional native leave is emitted. This establishes the source liveness cycle, not attribution of an unobserved HTTP packet in the older native failure.

Negative cases for any later repair: unacknowledged/intermediate transition; stale report or native movement; incorrect map/instance/position; superseded command/revision/runtime/route; cancelled or paused owner; no original pre-transition release; unrelated leg-arrived label; current attacker/safety context. Native gameplay verification remains mandatory. No production code is amended for this initial reproduction.

The isolated source cycle uses real sharedCommand generation with a noncontinuous convoy returnLegs array; command.returnLeg is true. Continuous returns generate returnLeg false and instead send /convoy-complete. The older Pumpkin logs indicate continuous-return Town policy, so this reproduction establishes a separate reachable source issue and does not identify that native failure without the pending HTTP evidence.

The second reproduction uses continuousReturn=1, real sharedCommand returnLeg=false, and the maintained /convoy-complete handler. After out-of-band native terminal settlement, Warrior reports arrived and sends convoy completion. The handler correctly returns waiting:true because Priest is still on its completion barrier; c.completed remains empty. Thus both real command variants reproduce the liveness cycle without inventing a returnLeg/continuous combination.
